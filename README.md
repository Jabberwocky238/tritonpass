# tritonpass

Triton's TTIR to block-level standard MLIR (`func` / `arith` / `math` / `scf` / `memref` / `linalg`), in Rust, on top of
[mlirformat](https://github.com/Jabberwocky238/mlirformat) (syntax: MLIR text ⇄ IR ⇄ typed ops) and
[mlirpass](https://github.com/Jabberwocky238/mlirpass) (pass manager, rewriting, dialect conversion, upstream passes).

It pins **Triton 3.7.1** (`third_party/triton`, `f797708c0`) and ports the structured-access analysis of
[triton-shared](https://github.com/facebookincubator/triton-shared) (`third_party/triton-shared`, `9424867`).
Any backend that takes standard MLIR can sit below it.

```text
  TTIR (Triton's str(mod), custom form with locs)
     │  tt / tts / ttg dialects + triton-* passes
     ▼
  block-level standard MLIR  ⇒  your backend
```

## Use

```rust
use mlirpass::mlirformat::MlirOpt;
use mlirpass::{Interfaces, Passes};
use tritonpass::{TritonPasses, TtInterfaces, load_triton};

let mut opt = MlirOpt::upstream();
load_triton(&mut opt);                 // tt / tts / ttg, with the hand-written syntax
let mut interfaces = Interfaces::upstream();
interfaces.register(&TtInterfaces);    // tt folds and canonicalization patterns
let mut passes = Passes::upstream();
passes.with(TritonPasses::add);        // every triton-* pass, by name
```

then build a pipeline by name, e.g.
`builtin.module(triton-to-structured, cse, canonicalize, triton-to-unstructured, triton-arith-to-linalg{grid-encoding=gpu}, structured-to-memref, triton-ptr-to-memref, reconcile-unrealized-casts)`.

## What is in it

| part | what it is | ported from |
|---|---|---|
| dialects | `tt` (generated from Triton's `TritonOps.td`, hand-written syntax where Triton's is in C++), `tts`, minimal `ttg` (`ttg.barrier` only) | Triton 3.7.1, triton-shared |
| `triton-to-structured`, `triton-to-unstructured` | pointer arithmetic ⇒ structured windows (`tts.make_tptr`), masks ⇒ per-dim extents; the rest ⇒ gather / scatter | triton-shared `PtrAnalysis`, `MaskAnalysis` |
| `triton-arith-to-linalg`, `structured-to-memref`, `triton-ptr-to-memref` | tensors ⇒ `linalg`, windows ⇒ `memref` views | triton-shared |
| `triton-lift-cf-to-scf`, `triton-drop-dead-exit-switch` | multi-block `tt.func` ⇒ `scf.if` / `scf.index_switch` | MLIR `CFGToSCF` |
| `triton-binary-search-to-for`, `triton-loop-*`, `triton-normalize-loop-index`, `triton-carried-buffers-in-place` | loops: bounded binary search, zero lower bound, unit step, no memref carried | — |
| `triton-fold-uniform-lanes`, `triton-fold-iota-integers`, `triton-split-row-axis`, `triton-squeeze-unit-dims`, `triton-conditional-fold-unit-dims` | index tensors back to scalars, rows that are products of two indices, unit dims | MLIR `DropUnitDims` for the last |
| `triton-lower-bool-ptr`, `triton-scalar-ptr`, `triton-drop-assume`, `triton-drop-thread-barrier` | pointer and op clean-ups | — |

Comments in the sources are Chinese for now.

## Tests

`cargo test --release --test passes -- --nocapture` runs every fixture in `tests/fixtures` chunk by chunk and compares the
generic printing byte for byte with the C++ implementation these passes were ported from (outputs checked in, regenerated by
`scripts/fixtures.py`). Two groups: the per-pass lit cases, and 360 TTIR kernels (vLLM, FlagGems, Triton's own tests)
through the whole pipeline.

`0.1.1` (mlirformat 0.6.3 / mlirpass 0.8.5): 362 chunks match exactly; 150 differ, 170 fail, 11 use an option not ported yet. The known gaps:

- the C++ default `triton-arith-to-linalg` (grid ids as six trailing arguments, `grid-encoding=args`) is not ported;
  every such case is also run with `grid-encoding=gpu`
- `tt.call` is not converted to `func.call`
- `tts.*` and `scf.index_switch` in custom form are not parsed (generic form is)
- floats are printed as written in the input, not re-printed as `1.000000e+00` (mlirformat)

`FLOOR` in `tests/passes.rs` only goes up.

Regenerating the dialect tables: `scripts/gen_traits.py` reads the ODS straight from the two submodules
(`git submodule update --init`).
